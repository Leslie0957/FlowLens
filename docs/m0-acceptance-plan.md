## 3. 测试先行与交付物

确认后顺序：上游/版本核验 → 最小测试设施 → 关键行为失败证据 → 最小实现和日志 → 确定性回归/人工探针 → ADR 和进度交付。

- 协议、工具权限、取消/预算、引用、配置隔离和脱敏先写测试。记录因能力缺失而失败的命令/原因，再记录通过结果；安装失败、语法错误、用例无法收集不算有效红灯。
- SQLite 用隔离临时数据库验证真实驱动/事务，只清理本次临时目录，不创建业务迁移或用户数据库。
- 合成 fixture 只验证读取/协议，不建设完整 S00/S04/S05 模拟器，不替代 M4 的 6 条真实模型评测。
- 拟新增 probes/m0/ 最小探针和 docs/adr/0001-m0-technical-validation.md；更新 README 和现有进度。最终布局在上游核验后记录，避免重复实现。
- 拟提供 typecheck、lint、test、build、probe:mock、probe:failure、probe:live 等探针入口。当前尚不存在；交付时提供实际可复制 PowerShell 命令及退出码，不创建空应用启动脚本。
- 各项记录通过/失败/未执行；LIVE 单列，人工源码/许可检查不混入自动测试计数。

## 4. 人工验收步骤（实施后执行）

1. 检查 ADR 中固定 commit、许可依据/声明、复用文件、适配边界与版本验证结果。
2. 按届时 README 在 Windows 安装锁定依赖，执行类型检查、Lint、确定性测试、构建；对照验收 ID 与实际输出。
3. 执行 MOCK 探针：看到 FIXTURE/MOCK 独立标识、真实 handler 调用、工具状态、证据和唯一终态。
4. 执行失败探针（如工具超时），以安全错误返回的 trace_id 查询日志，定位工具/错误码/耗时/FAILED；取消用例不再派发工具。
5. 隔离进程以 LIVE 且不传 Key 启动，应明确缺配置，无网络请求、无 MOCK 回退；当前无需提供密钥。
6. 有本地 Key、授权和预算后执行真实流式/工具往返；当前保持未执行。成功也不代表 UI、审批、持久化闭环或 P0 通过。

## 5. 日志查看与保留

当前没有应用日志。M0 拟输出 JSONL 到本地控制台，验收时按需保存至已被 Git 忽略的 logs/m0/；无远程遥测。默认不长期写文件；若采用自动文件输出，先补大小/保留策略并验证。手工验收文件在阶段确认后按需删除，只删除明确的本阶段文件；长期证据保留脱敏摘要。

字段：timestamp、level、module、event、outcome、trace_id；按链路携带 request_id、run_id、session_id、turn_id、tool_call_id、provider_mode、model、prompt_version、duration_ms、error_code、usage。边界校验或生成 ID 并持续传递，不伪造不存在的链路字段。

拟用以下方式查询实际生成的纯 JSONL（路径由执行记录确定，当前文件不存在）：

```powershell
Get-Content .\logs\m0\failure.jsonl |
  ForEach-Object { $_ | ConvertFrom-Json } |
  Where-Object { $_.trace_id -eq '<失败探针返回的 trace_id>' } |
  Select-Object timestamp,event,outcome,tool_call_id,error_code,duration_ms
```

运行日志、用户可见执行事件、业务审计分别处理；M0 日志不代替后续阶段的事件持久化和审批事实。
