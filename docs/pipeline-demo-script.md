# FlowLens 五分钟车辆 Pipeline 演示

2026-10-07。演示使用本地合成数据。直接验收先 `pnpm build`、`pnpm demo:pipeline`，打开 <http://127.0.0.1:5180/pipeline>；A/B已经实际运行并保留失败现场，C待运行。开发方式仍可 `pnpm dev` 打开5173。稳定离线演示可在新终端设置 `$env:MODEL_MODE='MOCK'` 后启动。已有 LIVE 配置保持原样，选择 LIVE 时按实际网络进度讲解，不承诺固定成功时间。

| 时间      | 操作                                                                              | 讲述与核对                                                                                                                                                                                                                                                                                                                                     |
| --------- | --------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 0:00–0:35 | 创建 A，打开“实际源表与结构”，执行预览                                            | “实习中我处理 SQL 查询、结果校验和入库失败后的人工排障。这里用10条自行生成的车辆事件把流程做成可视化 Demo；速度小于1 m/s、持续至少3秒是预先固定的演示规则。” 看 `speed_mps`、时长边界和不应入库的对照样本。                                                                                                                                    |
| 0:35–1:05 | 返回工作台，运行只读预检                                                          | SQLite 实际报 `no such column: speed_kph`，突出 query 阶段失败。当前目标仍为空；重复运行同一错误 SQL 仍失败。                                                                                                                                                                                                                                  |
| 1:05–1:55 | 点击“Agent 取证并生成候选”                                                        | 按工具取证、诊断结论、修复候选查看，明确 LIVE 或 MOCK 来源。点击结论里的证据编号或下方证据按钮，核对实际返回内容；原始证据ID与版本仍可展开。展开工具可看调用返回JSON。当前提示词要求模型读取六类资料，工具由模型发起；本地读取很快，可能同时显示完成。模型只提议 `task.sql`，不能改数据、运行器或规则。看红/绿Diff，指出完整规则需要独立验证。 |
| 1:55–2:35 | 查看Diff后点击一次“批准修复并入库”                                                | 按钮说明同时授权当前候选与通过校验后的入库。后端记录批准时的目标版本/摘要，先隔离查询、校验、实际入库和重跑去重验证，通过才发布新SQL，再执行当前SQL只读预检。原失败与Diff保留；失败、取消或目标变化会停止，不追加写入。                                                                                                                        |
| 2:35–3:20 | 自动进入“入库结果复查”，核对本次新增4/跳过0及实际数据                             | 预检通过后后端使用原事务代码直接入库，不再要求第二次批准。执行/SQL/输入/输出/目标版本仍绑定，业务行、前快照与凭证同事务提交。自动化 E 在第二行 INSERT 触发真实错误，显式ROLLBACK无半批数据。正常SQL无Agent时，可在预检卡片直接批准入库。                                                                                                       |
| 3:20–4:05 | 在结果页查看自动查询的4行数据；打开查询页执行 COUNT、查入库前快照；返回重跑并批准 | 当前 COUNT=4，前快照0行。结果无误可“复查无误，完成”返回工作台，这只是结束复查，写入已在批准时提交。重复入库新增0/跳过4、没有重复数据；零写入批次无需撤销，最新有效数据头仍指向原批次。                                                                                                                                                         |
| 4:05–4:40 | 打开原有变更批次结果页，“发现问题，撤销本次入库”，核对范围并“确认撤销并恢复”      | 首次点击展示恢复范围，也可保留数据。确认后自动查询恢复后的0行、显示恢复凭证，data_version增加。SQL及原执行/诊断/审批历史保留。只能撤销最新有效批次，后端固定参数化恢复，不允许 Agent 提供恢复 SQL。                                                                                                                                            |
| 4:40–5:00 | 打开预先创建并实际运行过的 B                                                      | 查询返回4行但别名为 vehicle_type，因缺 car_series 在 validate 阶段失败。强调“退出码0也不代表业务正确”。展示 LIVE A/B 验收报告，说明有限样本和单用户本地边界。                                                                                                                                                                                  |

准备时可先创建并运行 B；保留实际日志，不用预写时间线。A/B 模型若本次失败，就展示失败和先前真实 LIVE 记录，不能把 MOCK 卡片称为 LIVE。页面刷新只读取持久历史，不会重新执行。选择旧执行可复看对应 SQL、日志与诊断，URL 保留 `execution`。

新版入口以车辆 Pipeline 为主；原运行监控、历史诊断、模拟演示和订单实验收在“早期实验与历史”，不需要加入五分钟主线。工作台“下一步”依据当前SQL版本提示操作，旧执行不会因修复成功而被覆盖。正文逐步呈现发生在模型生成与引用校验完成后，SSE同步真实状态与工具记录，不宣称实时模型token推送。

可讲述的结果：“FlowLens 在真实本地任务上让 Agent 取证、提出修改，再由人工审批和独立验证约束结果；业务数据写入与撤销由确定性事务代码完成。” 不宣称生产准确率、公司连接或无人审批的平台。
