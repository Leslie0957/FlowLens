## 1. 验证事实分开记录

| 维度          | 可以证明什么                          | 不能替代什么                         |
| ------------- | ------------------------------------- | ------------------------------------ |
| 真实本地执行  | 子进程实际查询、失败、退出与验证结果  | 真实业务连接、生产修复或任意代码沙箱 |
| MOCK Agent    | 工具协议、权限、审批、Diff和状态流程  | DeepSeek诊断与补丁质量               |
| LIVE DeepSeek | 指定样本中模型实际查询/提出补丁的行为 | 未测输入泛化或“永远修复成功”         |
| 人工验收      | 用户实际操作指定阶段并确认体验        | 尚未实现的后续阶段                   |

M6.1 不需要模型调用。M6.2/M6.3 LIVE 调用前核对当前授权；本机已有持续 LIVE 授权、每次输出2048 tokens，若用户未撤销不用逐次询问，但仍记录实际次数/usage并遵守任务预算。CI全部离线。

| L16 | 服务正常退出/异常终止后重启                               | 旧活动执行INTERRUPTED；日志仍在；不重跑；子进程不无限存活                 | 独立服务进程生命周期测试 |
| L17 | 日志超过200KB、单条超过2KB或产物超过64KB                  | 有界存储/响应；稳定限制错误；不把截断结果判为成功                         | 可信输出压力任务         |
| L18 | 数据库/目录/进程启动/产物写入失败                         | 可解释终态，关联ID可定位；不留下成功状态或重复执行                        | 故障注入+持久化核对      |

## 3. M6.1 人工验收操作

以下入口已实现，供本次人工验收使用。

1. 打开“本地执行实验”，创建 SQL 列错误项目；确认此时尚未运行，看到源码引用order_total和三条合成输入。
2. 点击“运行任务”；确认显示LOCAL_EXECUTION/SYNTHETIC，看到SQLite错误、实际退出信息和失败验证结果。
3. 不改源码再次运行；确认是新执行、同一版本、继续失败，旧日志仍可打开。
4. 创建并运行“正常对照（预置）”；确认结果为3笔/总额100，页面不声称Agent已修复。
5. 刷新并切换旧执行；确认输入、源码hash、日志和结果完整，页面不重新执行。
6. 使用实现者提供的可取消测试任务验证取消；若普通SQL完成太快，不能把“点不到取消”当取消验证通过。
7. 回到S04旧场景，确认仍是FIXTURE模拟审批；确认现有聊天未被清空。

自动化与上述人工确认通过后，才记“M6.1验收通过”。这不代表M6.2修复能力已经实现。
