2026-10-08。此前工作区的已有修改已整体保存为提交 `0074bbf`（未推送）；本次修复在该提交之后实施。保留用户项目和历史记录，未修改 `.env.local`。全部执行、批准入库与撤销评测使用新建隔离合成数据库。

## 两个问题及实际改动

此前 LIVE 模型在第一次请求就选择六个工具，第二次请求提交结论；后端反馈循环存在，但没有观察到收到工具证据后选择另一项读取。单改提示词仍出现同轮 get_sql + get_schema，不能算作多轮取证。

现在全部六个工具定义仍可供模型选择，没有按模板、失败阶段或异常字符串安排生产调用顺序。首份成功工具观测之前，允许模型请求一项工具或给出有依据的非修改建议；如果请求批量读取，所有调用仍进入 ToolRegistry 的白名单、参数与绑定检查，逐个记录 FAILED / REPAIR_FIRST_OBSERVATION_REQUIRED，并按原 call ID 返回明确的“暂缓读取”反馈，不实际读取或生成证据，不偷偷只执行第一个。模型重选一项后，收到实际结果再决定继续还是结束；之后仍支持同轮多项独立读取。初始错误加单个 get_sql 仍可形成合格候选，没有固定最低取证轮数或六项必读门槛。重复暂缓同样计入调用、请求和无进展限制。

混合调查 JSON 说明与原生工具调用时，首个 LIVE 试验观察到模型返回文字形式的 DSML 标记，实际 calls=[]。Pipeline 现显式关闭共享网关的强制 JSON response_format，最终答案仍由原有 JSON / Zod / 来源校验检查；其他 Agent 的默认 JSON 模式保持不变。只处理原生 tool_calls，不把文字标记解析成可执行工具。新增协议测试验证分块原生调用与说明共存，并确认工具形状的文字不会执行。配置语义可查 [DeepSeek JSON 文档](https://api-docs.deepseek.com/guides/json_mode/)及[工具调用文档](https://api-docs.deepseek.com/guides/tool_calls/)；上述错误和修复效果来自本机实际轨迹，不推断所有提供商都有同样行为。

页面根据实际 model request 分组，显示调查问题、公开的信息缺口说明、所引用的实际证据，以及本轮原生调用与返回。新增 MODEL_DECIDING / TOOLS_RUNNING / ANSWER_CHECKING 阶段随持久化快照更新。等待模型选择时显示正在评估上一轮证据；首轮批量暂缓明确显示“已暂缓”。说明只有结构合法且引用已存在证据时才展示，原始回复保留；不输出隐藏思维。旧记录缺少轮次时注明“轮次未记录”，同轮六工具不会被伪拆成六轮。

历史面板此前将同一批准版本的所有 PRECHECK 关联到旧修复。现在只按三个真实关联编号显示：repair.execution_id 的原始失败、verification_execution_id 的隔离验证、commit_approval.execution_id 的已批准入库预检。面板注明所选执行、诊断来源和当前关系，同一个修复的三个执行仍共享原始失败诊断，但上下文会变化；右上角注明是该修复流程最新状态。普通同版本重跑显示“未生成关联诊断”，可通过来源按钮回到原始修复。执行切换重新挂载对应面板并关闭证据弹窗，避免保留旧执行的弹窗状态。

本次证明两条样本中确有收到上一轮实际证据后的不同选择，公开说明的证据引用可核对；不是反事实实验，也不宣称通用模型决策准确率。A 的 get_schema 实际返回还包含 contract，最终提及规则有已返回来源，无需额外 get_task_contract；工具描述已补充这一点。来源校验不会自动证明所有自然语言推断，实际 SQL 正确性仍由审批后的独立验证器验证。原文保留在报告中。

有既有付费授权时，可重跑 `pnpm eval:pipeline:feedback`，默认最多 8 个共享请求，可设 FLOWLENS_PIPELINE_EVAL_LIVE_MAX_REQUESTS（仍受既有授权约束），或传 --fixture=A / --fixture=B。每次创建新的 logs/pipeline/feedback-live-*，不覆盖历史报告。评测要求至少两个成功取证请求，后续公开调查说明引用实际已返回工具证据；暂缓或失败调用不算成功取证轮次。

现在结构化说明继续带实际证据按钮；普通公开 assistant 说明使用文本原样显示为“模型调查说明（原文）”，不会生成翻译、补造结论或证据。非法 JSON / 未通过验证的结构化说明及 DSML 工具标记不提升为有效调查说明。内容以 Vue 文本插值渲染，HTML 不执行；最终回复不会被当成取证说明。

页面将本会话内工具名、规范化参数和实际 output 一致的再次读取标记为重复，指明原先请求轮次；新 evidence ID 不算新观测，业务值变化仍视为不同结果。首次批量暂缓解释为平台调度反馈，保留原始错误对象，避免误认为 SQLite / 工具故障。提示词补充使用 schema 已包含的 contract、复用已读取 SQL 的 base_hash 和证据 ID、已有依据时结束；提示词不能保证模型永不重复，本次未发起新的付费试验。
