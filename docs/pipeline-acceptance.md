## 已发现失败与修正

- 初次工具命令遇到 pnpm 工作区路径 EPERM，改为获准的本地验证执行；未以绕开保护的方式读取密钥。
- 首次定向HTTP测试发现非法SQL返回500，已映射为有界策略错误400；真实未知列查询返回422和SQLite错误。
- 初次全量回归：旧测试通过最新schema再删旧表模拟旧库，未删新Pipeline表，导致迁移冲突；旧断言停在v9。更新测试夹具模拟真实旧库及v10断言，旧历史保留断言仍执行。未修改已应用旧迁移逻辑。
- 初次浏览器检查：新Element Plus组件未按需导入；已修正。之后发现刷新后批准会自动切换到最新验证执行，导致原诊断消失；已固定选择并保存execution URL。
- 浏览器测试还修正了Element Plus选择框的键盘操作定位及重复日志/预检文本的严格匹配；这些测试失败记录保留在 `e2e-second.txt`、`e2e-third.txt`，没有把它们当作通过记录。
- 收尾核对第13节补齐查询前的实际字段/类型显示。真实进程退出测试发现应用入库审计成功核对后仍缺批次链接，已从目标原子凭证补齐；没有重做业务写入。

## 已知限制与未验证事项

- 本地单进程、小规模合成数据；不接公司环境，不支持外部客户端直接修改目标库、多租户、任意Shell、通用调度、JOIN/CTE/任意数据库管理。
- SSE传递状态变化通知，再读取完整有界快照；实时模型初稿不显示为正文。每项目列表最多100版本/批次、50执行、30诊断/100操作，数据库完整历史保留；尚未建设历史分页浏览器。Diff为完整文件前后对照，不是大型SQL IDE。
- 主库用独立JSON实体保存新链路状态和不可变快照；业务目标库的批次/恢复凭证是数据事实来源，不假设跨库事务。验证目录保留可信初始目标hash与真实提交记录；未提供Agent自由恢复SQL。
- 原始源数据只读且核对logical input hash，首版没有新输入版本上传流程。可编辑 SQL 仍须符合小语法；语义错误由实际独立验证拒绝。并发与超时针对固定小规模输入，不声称大库性能。
- 已测试真实进程在目标提交/恢复后、应用审计写完前退出；重启恢复SUCCEEDED及批次链接，重试不增加批次/恢复记录/版本。另覆盖重复恢复和活动执行中断。未对每个事务边界进行操作系统断电/磁盘故障注入，也未验证跨机器、长时间网络离线或公网部署。
- 人工LIVE浏览器验收仍未做；用户可按五分钟操作稿进行。没有待补密钥/授权问题，本轮没有推送、提交或部署。
