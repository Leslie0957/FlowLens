## 实施顺序与证据

先盘点状态机/事件与适配接口，再按流恢复与会话隔离、取消、重启、并发审批、适配契约顺序补行为测试并修复。复用已有测试，未改动部分不反复建立测试账本。重大协议/持久化变更先记录兼容与迁移影响，不把普通重构变成整体重写。

优先使用确定性模型/网络故障注入；Mock 只替代外部响应，真实业务状态、事务和持久化继续执行。M3 默认不产生付费模型调用；若明确需要额外 LIVE 检查，先说明目的与次数，取得相应授权。用户此前手工 LIVE 验收与代理执行额度分别记录，不从历史授权推算余额。

阶段结束运行类型检查、Lint、相关单元/集成、构建及浏览器回归，并逐项对照所有 P0 AC 报告通过、失败和未执行。6 条正式真实模型质量评测属于 M4，不用 Mock 冒充。

## 人工验收与日志

使用独立测试服务：发送诊断时刷新；中断流后恢复；A/B 快速切换；生成中停止；重复批准；诊断/模拟运行中重启。分别检查无重复消息、无串会话、取消终态不回退、只有一个 child、重启后终态与日志可恢复。自动化先覆盖，用户主要复核交互及可读性。

沿用白名单 JSONL，以 request_id/session_id/turn_id/approval 或 run 关联查找恢复与失败；按需补稳定错误类别，不输出 Key、完整 Prompt 或工具正文。测试日志放 Git 忽略的 logs/m3，默认保留策略沿用 README。实际失败演练与筛选命令在实施后记录，不把计划当成执行结果。

## 退出条件

所有适用 P0 AC 有实际证据且无未解决阻断项；并发、晚到事件和重启不能破坏数据不变量；历史库可升级；用户人工复核通过。阶段结束更新 implementation-progress，等待确认后进入 M4。
