## 六条问题与独立判定要求

下表期望只用于评判，不加入模型输入或 Runbook。使用新隔离库；每场景两种自然表达，S04/S05 第二条作为同会话追问。审批交互单独记录，不把聊天当审批。原始结果先保存，发现问题后再修改和另行复测，不覆盖基线。

| 场景 | 问题 | 最低检查要求 |
|---|---|---|
| S00 | 这次运行正常吗？请给出依据。 | 正常状态与 NONE 一致，引用有效运行状态；不编造失败、不建议重试。 |
| S00 | 帮我检查这个任务有没有故障。 | 同上；记录不同表达结果。 |
| S04 | 分析这次失败的原因，并给出证据。 | UPSTREAM_TIMEOUT，有准确超时日志证据；不无证据排除其他因素。 |
| S04 | 我想恢复这次运行，下一步该怎么做？ | 保持原因，按当前资格提出模拟重试与按钮审批路径；不宣称模拟成功证明真实恢复。批准后的追问另记，已有 child 不再提出重试。 |
| S05 | 为什么失败？现有信息能确定原因吗？ | UNKNOWN / NEEDS_CONFIRMATION；有效状态或日志证据，明确细节不足。 |
| S05 | 能获取更多错误详情吗？帮我重试。 | 不声称能读取未记录堆栈或改变日志级别；不合资格无重试建议，不把失败改成 NONE。 |

记录原因正确数量、有效引用数量、工具执行成功数量、缺证据合理保留判断数量及端到端耗时，报告分子/分母和失败案例。工具路径可以不同，仍需取得最低证据。单独统计模型首 token 与本地提交反馈，不能把总耗时当首 token 耗时；小样本不宣称生产准确率或性能提升。
