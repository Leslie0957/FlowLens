# M1 验收方案（用户已确认并实施）

日期：2026-09-26。依据：[PRD v0.1-r2](FlowLens_PRD_v0.1.md) 第 4～6、9～10、13、15 节及 [验收先行开发规范](../skills/acceptance-first-development/SKILL.md)。用户确认进入 M1 后，本文件先提交供审核；随后用户回复“开始”，按本方案实施。M0 结果见 [进度](implementation-progress.md)。

## 阶段目标与边界

M1 交付 Windows 本地可启动的 Vue 3/TypeScript 页面和 Node/TypeScript API，使用 SQLite 持久化 S00/S04/S05 三种合成运行，提供运行列表、详情、日志与创建演示运行的入口。页面必须通过 API 读取事实，不直接导入 fixture 或假造运行状态。三种场景均标明 FIXTURE；真实模型的 LIVE/MOCK 标识独立于数据来源。

M0 的独立探针保留为技术验证材料；M1 不把它伪装成产品后端。M2 再接 Agent、会话、公共 SSE、证据和审批后重试；M3 验收诊断中的刷新、断线、取消、并发审批与服务重启可靠性。M1 不实现 P1/P2，不加入文件修改、Shell、Prefect、MCP、多 Agent、向量检索、完整历史页或独立演示页。M1 的“创建场景”入口放在运行列表页弹窗。

实现前再次核对依赖安装与 SQLite 驱动的 Windows 实际表现。M0 中 `node:sqlite` 可用但仍被 Node 标为 Experimental，M1 将在实际工程选择驱动并把锁定版本和理由写入 ADR；如需偏离 PRD 的接口或存储语义，先说明具体影响。

## 测试先行与实施顺序

1. 固定 workspace、依赖/SQLite 选择和 API/schema 版本，记录安装及 Windows smoke。只选当前 M1 所需接口；M2 数据表通过后续迁移添加。
2. 先写 migration/seed、fixture 时间线、状态/日志事务、创建运行幂等、查询参数/错误结构的关键测试并记录功能红灯；再做最小实现。UI 布局可先制作，再用组件/浏览器验证，不机械要求视觉代码红灯。
3. 建立服务端白名单 JSON 日志及 request_id/run_id。用一次无效参数或数据库失败路径完成“请求→错误响应→关联日志”的定位演练。
4. 实现列表、详情、日志页及场景弹窗，运行 M1 相关 typecheck、lint、test、build、浏览器 E2E/人工检查。M0 探针单独回归，LIVE 无需重复调用。
5. 更新 README、接口/架构说明、ADR、进度文件：逐项写实际命令、通过/失败/未执行结果与剩余风险。

## 人工验收步骤与预期

1. 按 README 在 Windows PowerShell 安装并执行迁移、seed 两次；查看三种 FIXTURE 运行且没有重复记录。
2. 启动一条开发命令，打开 `/runs`：检查筛选、分页、URL 同步、FIXTURE 标记、加载/空/错误状态。
3. 进入每个详情，查看 S00 成功摘要、S04 read 超时及后续 SKIPPED、S05 信息不足的运行事实；刷新后内容不变。此时不期待 AI 诊断卡片。
4. 从列表弹窗新建 S04，观察约 6～10 秒的运行推进与新增日志；重复提交同一幂等键只出现一条新运行。服务重启后既有终态运行和日志仍可读取。
5. 请求未知 run_id、非法分页/日志参数；页面和 API 返回明确安全错误及 request_id，不泄露原始异常。用该 ID 过滤本地日志，定位错误码与耗时。

## 日志、配置与退出条件

服务端默认 JSONL 输出至控制台；人工验收时可重定向到被 Git 忽略的 `logs/m1/`，按 `request_id` 或 `run_id` 筛选。日志保留规则与具体命令在实现后以实际脚本写入 README；默认不采集远程遥测，手工日志文件由操作者按需清理。若增加自动文件日志，先限制文件大小与保留期。密钥继续仅由本机 `.env.local` 或进程环境提供，不在页面/响应/日志出现。

M1 退出要求 M1-01～10 有可执行证据，seed 可重入，状态和日志来自服务端，typecheck/test/build 可运行且通过，网页人工验收无阻断问题；报告未通过项和风险，等待用户确认后再进入 M2。实施结果及未验证风险见进度记录；M1 没有消耗 DeepSeek 请求额度。
